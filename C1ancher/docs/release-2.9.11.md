# C1ancher 2.9.11

## 自动关机

本版目标是修复 2.9.10 对输入过的终端会话永久阻止自动关机的限制：普通命令执行完成、终端处于可确认的空闲状态且没有需要保护的任务或未提交输入时，可以在自动关机到期后关闭桌面自有终端。仍在执行的前台、后台、停止及脱离会话的任务，以及无法可靠确认的状态，继续受保护；不通过强杀真实用户任务来实现关机。

应用、网络任务、显示占用及不安全更新状态的关机保护仍保留。省电模式为无操作1分钟锁屏、锁屏后再2分钟关机；标准为3分钟锁屏、锁屏后再5分钟关机；性能模式不自动关机。插电或电源状态未知时暂停自动电源动作。

## 单一正式更新入口

今后只维护 `stable` 正式更新通道。为兼容已有设备，原 `/c1/core/v1/canary` 地址保留，但由服务端读取同一正式版本，不再发布或维护独立测试版本。旧设备不需要更换公钥或为了这个地址变更重新安装。

核心发布仍仅包含 `C1ancher`、`c1pkg`、`C1ancher-launcher`、`c1updater` 四个组件；不发布独立输入法。服务端改动只部署必需产物，不公开服务端、发布器、Windows安装器或InkWars源码。

## 应用数据目录

阅读器 0.1.23 与音乐播放器 0.3.6 已于 2026-09-26 独立发布并完成公网验签回验（应用目录序列 179）。它们分别把默认用户数据目录改为 `/storage/c1/book-reader` 和 `/storage/c1/music-player`。这两个应用更新与核心更新是分开的，需要在应用列表更新对应软件，安装新核心不会自动替换应用包。

按维护者要求，不读取、复制或自动迁移旧 `/usr/data` 目录中的阅读进度、书签及播放器设置，也不在大分区不可用时回退至小分区。新版本使用新位置中的状态；没有新状态时按首次使用处理。原书籍和歌曲仍在 `/storage/mtp/Book`、`/storage/mtp/Music`，不搬动媒体文件。

继续沿用更新确认后的 `/usr/data` 清理策略。旧应用若尚未更新，仍可能向会被清理的旧目录写入；升级新应用也不意味着旧阅读进度自动恢复。`/storage` 不在核心清理范围内。

## 发布与验证记录

2026-09-26，单正式通道后端和上述两个应用已经分别上线并回验；核心线上仍为序列 28 / 2.9.10。2.9.11 核心尚未冻结、签名或发布。

终端新空闲检测需要设备自带 Bash 的动态模块及 Readline 接口支持；主机测试和 MIPS 模块交叉编译不能证明实际固件兼容。本次 ADB 未连接设备，本地也没有可用的对应固件。维护者已选择暂不提供目标环境，因此保留已发布应用，核心 2.9.11 等待设备或对应固件验证。之后先做只读兼容检查，不以此决定授权真机关机或刷写；无法确认空闲时继续保护会话，不冒险终止用户任务。

当前安装检查只接受已核验的 Readline 8.1 或 8.2；主机测试覆盖 8.1/8.2，当前目标设备为 Bash 5.2.15、动态 Readline 8.2。目标 ELF 已核对所需 Bash/Readline 符号、MIPS o32 ABI 及 `/dev/shm` 挂载；仍需要在设备上实际加载该模块并做一次 PTY 回归，才能完成发布门禁。旧版或静态 Bash、缺少所需动态符号、或 `/dev/shm` 不允许执行映射时，模块会显示诊断并保护会话，普通命令完成后自动关闭的修复不会生效。

本地终端专项工作已完成四组件兼容嵌入、生命周期与故障回归、自动关机集成测试、四个 MIPS 程序构建及嵌入内容检查。主机 Bash 实际加载 ASan/UBSan 插桩模块的生命周期与故障测试通过；该专项关闭泄漏检查，系统 Bash 自身及目标 MIPS 运行环境未被插桩。此前模块加载失败的尝试不计为通过。这些结果仅覆盖当前工作区的终端专项，不是最终冻结核心的全套发布验证，也不构成目标设备兼容证明。

本文件描述核心本版预期行为。只有冻结源码的完整主机、生命周期、目标构建、内存安全、目标 Bash 兼容、旧更新器、源码重建及服务器公开下载校验通过后才正式发布；实际发布版本、序列、摘要及验证结果另行记录。主机和模拟测试不能替代真实设备物理断电、冷启动与连续自动关机验收。
